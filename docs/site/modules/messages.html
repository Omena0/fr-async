fr_async.messages

Message objects are yielded by tasks to request work from the event loop. Registration messages arrange for the loop to resume a task when an event occurs; execution messages run their blocking operation in the loop's thread pool.

Exported classes

The module's all contains the following classes:

  • Message — base class for yielded operations. Source
  • BackgroundMessage — message with detached/background execution support. Source
  • Messages — groups messages that a task waits for together. Source
  • Sleep — waits for a monotonic-clock deadline. Source
  • WaitReadable — waits for socket readability. Source
  • WaitWritable — waits for socket writability. Source
  • Accept — accepts all currently queued connections. Source
  • ToThread — runs a callable in the thread pool. Source
  • AsCompleted — exposes thread-pool results in completion order. Source
  • TaskJoin — waits for one task and returns its result. Source
  • TaskGroupCollect — collects task results in input order. Source
  • TaskGroupAsCompleted — exposes task results in completion order. Source
  • FileRead — performs a file read in the thread pool. Source
  • FileWrite — performs a file write in the thread pool. Source

Additional public module names

These names are defined without a leading underscore, but are intentionally omitted from all:

  • MessageWithSocket is the shared base for socket messages. Source
  • check_resolved(blockers: deque[Message]) -> bool removes resolved messages from the front of a blocker queue and reports whether it is empty. Source
  • register_event(message: MessageWithSocket, task: Task, event: int) registers a socket message with the current loop's selector. Source

The helpers are implementation-facing; normal applications should yield the message classes rather than call these helpers directly.

fr_async.init imports the names in this module's all into the package namespace. The package itself has a narrower all, so explicit imports such as from fr_async import Sleep work, but from fr_async import * does not include message classes.

Message lifecycle

A task yields a message. The loop calls register() for registration-based messages or submits execute() for execution-based messages. When the message is resolved, the task becomes eligible to run again. The exact value sent back into the generator is defined by the message type and its typing annotation.
